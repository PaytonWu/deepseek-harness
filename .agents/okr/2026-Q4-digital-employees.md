# OKR：数字员工（Digital Employees）

状态：进行中（2026-11-11 创建）
关联：[spec](../specs/digital-employees.md) · [TDD plan](../plans/digital-employees-tdd.md)

## Objective

用户在 dsh 中拥有自己创建、可直接对话、记忆可延续的数字员工队伍：每个员工是一个具名、可管理的 pi 编码代理实体，有固定的职责、工作目录和持久的 pi 会话身份；用户与员工的交互是一等公民，不依赖 dsh 主模型的自由发挥。

## Key Results

### KR1 员工可创建、可管理

用户通过 UI 向导创建、编辑、删除数字员工：向导收集名称、职责描述、工作目录（浏览选择）、可选的已有 pi 会话导入；创建后员工立即出现在侧边栏"我的数字员工"命名分组下，并有自己的会话入口。

- 验收：向导全流程可走通；编辑即时生效；删除有确认；全部 UI 文案走 locale 字典（8 语言）。

### KR2 员工会话端到端可用

在员工会话中发送的消息**直通**绑定的 pi 子代理（不经 dsh 主 LLM 转述），pi 的回答回显为助手消息；运行中可中断；职责描述在 pi 会话首次创建时作为开场指令注入。

- 验收：一轮真实对话（用户消息 → pi 回答）在 Web UI 可见、可中断；消息链路不调用 dsh 主模型。

### KR3 记忆与配置跨重启延续

员工配置（名称/职责/cwd/pi 会话绑定）持久化于 `$DSH_HOME/pi-agent/`；Host 重启后员工、分组、会话映射完整恢复；同一员工的新任务续用同一 pi 会话（跨任务记忆）。

- 验收：重启 Host 后员工仍在分组下，继续对话能引用该员工先前会话内容（pi 会话文件延续）。

### KR4 质量门槛全绿

stub 单测覆盖员工目录、会话路由、持久化与导入；keyless 快照覆盖向导与一轮员工对话；真实 pi e2e 无 pi 自跳过；仓库现有全部 gates 保持通过。

- 验收：`test:coverage` 新代码达标；快照进 `test:snapshot`；doc-sync / lint / typecheck / constraints 全绿。
