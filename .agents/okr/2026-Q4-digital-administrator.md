# OKR：数字管理员（Digital Administrator）

状态：进行中（2026-11-13 创建）
关联：[spec](../specs/digital-administrator.md) · [TDD plan](../plans/digital-administrator-tdd.md)
底座：[数字员工](2026-Q4-digital-employees.md)（员工目录、pi-as-model 直通、分组与向导）全部复用；本 OKR 在其上新增管理层。

## Objective

用户在钉钉上拥有一个数字管理员：一个管理层数字员工实体，与用户的钉钉账号 IM 通信——把绑定数字程序员的反馈实时转发给用户，接受用户在钉钉里的自然语言指令，管理（创建/销毁/派活/查询）一组绑定的数字程序员。管理动作的权限与级联语义由确定性代码强制，不依赖 LLM 自觉。

## Key Results

### KR1 数字管理员可创建、可双面对话

创建向导新增类型步骤（数字程序员 / 数字管理员）；数字管理员获得 pi-as-model dsh 会话（web 直接对话，无工作目录字段）并按钉钉通道接入 IM。管理员可销毁（dsh 删除流），销毁时其绑定员工全部解绑不删除。

- 验收：向导两类型均可创建；管理员在 web 可直接对话；销毁管理员后绑定员工仍在且 `managerId` 清空。

### KR2 反馈链路可靠

被绑定数字程序员的会话回合结算即反馈：格式化消息（发送者、内容截断）经钉钉 IM 到达用户。发送失败退避重试 3 次，仍失败落日志与会话提示，不阻塞员工继续工作。

- 验收：员工一轮对话完成后用户钉钉收到反馈；人为断网场景重试 3 次后降级，员工会话不受影响。

### KR3 双向指令闭环

用户在钉钉回复管理员消息：经 userId 白名单校验注入管理员的 dsh 会话，LLM 经工具调用执行，回复文本回发钉钉。工具集：创建数字程序员（自动绑定本管理员）、销毁（仅限已绑定，自动解绑；未绑定拒绝）、列出员工与状态、派活（注入员工会话）、查询员工中间状态（运行/空闲、最近反馈、最后活跃）。绑定与权限校验全部在工具实现里强制。

- 验收：IM 自然语言指令可创建（自动绑定）、销毁（未绑定拒绝）、派活、查询；工具实现的越权用例（销毁未绑定）单测覆盖并拒绝。

### KR4 绑定语义与通道解耦

绑定关系持久化于员工记录（`managerId`）；创建自动绑定（唯一管理员自动，多个显式选择）、销毁自动解绑。收发抽象为可替换 Transport：v1 落 dws（私人通知群发送 + `dws event` 长连接接收），企业机器人应用为后续配置即切的实现；通道配置入 dsh settings。

- 验收：绑定关系的建立/解绑/级联单测覆盖；Transport 接口契约测试；settings 配置字段生效。

### KR5 质量门槛全绿 + 全链路真机验收

stub 单测覆盖数据层/管线/工具/白名单；仓库现有全部 gates 保持通过；全链路真机 SMOKE：创建管理员 → 钉钉收生命周期通知 → IM 派活 → 员工执行 → 反馈回钉钉 → IM 指令创建/销毁员工（含未绑定拒绝）。

- 验收：`test:coverage` 新代码达标；lint / typecheck / doc-sync 全绿；SMOKE-PASS。

## 非目标（本 OKR 周期）

- 飞书通道的数字管理员实现（通道抽象与 Transport 接口就位，实现后续周期）
- 钉钉企业机器人应用身份实现（接口就位；v1 以 dws 通知群收发）
- 管理员的上级（管理员的管理员）、多管理员共管同一员工
- 群聊多成员指令、反馈的持久化补发队列
- 数字程序员自身获得管理能力（一线定位不变）
