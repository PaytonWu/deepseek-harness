# Spec：数字管理员（Digital Administrator）

状态：已评审（2026-11-13，与 OKR [2026-Q4](../okr/2026-Q4-digital-administrator.md) 对齐；设计经 grill 会话逐项确认）
关联：[TDD plan](../plans/digital-administrator-tdd.md)（交叉验证矩阵见文末）
底座：[数字员工 spec](digital-employees.md) 的员工目录、pi-as-model 直通 adapter、分组与向导全部复用；本 spec 在其上新增管理层。

## 1. 术语

| 术语 | 定义 |
|---|---|
| **数字管理员**（admin） | 管理层员工类型：与用户钉钉账号 IM 通信，接收绑定数字程序员的反馈并转发，经 LLM 工具调用创建/销毁/派活/查询员工。 |
| **数字程序员**（pi-coder） | 一线执行员工：负责任务执行与结果反馈，无管理能力（不管理其他员工）。 |
| **绑定**（binding） | 员工记录上的 `managerId`：一个数字管理员管理一个或多个员工；每个员工至多一个管理员（v1）。创建即绑定，销毁即解绑。 |
| **通道**（channel） | 管理员的 IM 实现维度（`dingtalk`，后续 `feishu`）；管理职责逻辑与通道解耦，收发抽象为可替换 Transport。 |
| **反馈**（feedback） | 被绑定数字程序员的会话回合结算事件：最后的回答文本经管理员层转发到用户钉钉。 |
| **Transport** | 钉钉收发的可替换实现接口（send/receive）；v1 为 dws 实现，企业机器人应用为后续实现。 |

## 2. 用户场景

### S1 创建数字管理员（UI 向导）

创建向导第一步新增类型选择：**数字程序员**（一线执行）/ **数字管理员**（管理层）。选数字管理员后字段精简：名字（默认"数字管理员 N"递增）、头像（类型预设 emoji）、默认模型、思考强度——工作目录隐藏（固定为分组目录）。职责描述由类型模板填充。

确定后：管理员写入目录并获得 pi-as-model dsh 会话（分组下出现其入口，web 可直接对话），同时按 `channel: dingtalk` 接入 IM 通道（长连接接收 + 通知群发送）。

### S2 反馈转发

被绑定数字程序员的会话回合结算后，管理员层组装消息：

```
【数字程序员名】反馈：
<最后回答文本（超 2000 字符截断，附省略提示）>
```

经 Transport 发到用户的钉钉通知群。发送失败退避重试 3 次，仍失败写 Host 日志并在管理员会话提示；员工侧不受任何影响。管理员的创建/销毁动作同样通知用户（生命周期审计）：

```
【系统】已创建数字程序员"X"（已绑定本管理员）
【系统】已销毁数字程序员"X"（已解绑）
```

### S3 双向指令

用户在钉钉里回复管理员消息：

1. 事件经长连接到达，先过 **userId 白名单**（settings 配置）：非白名单发送者一律忽略，不留痕；
2. 白名单通过 → 消息（带来源元数据）注入管理员的 dsh 会话作为用户指令；
3. 管理员 LLM 理解意图并调用管理工具执行，回复文本回发用户钉钉（对话闭环）。

指令示例与实际效果：

| 用户说 | 实际发生 |
|---|---|
| "创建一个数字程序员，目录 D:/repo，叫小张" | 工具创建员工"小张"（cwd=D:/repo），自动绑定本管理员，IM 通知生命周期 |
| "把数字程序员3解雇了" | 绑定校验：`managerId` 指向本管理员 → 销毁并解绑；未绑定 → 拒绝并说明 |
| "现在都有谁，谁在忙" | 列出绑定员工与运行/空闲状态 |
| "让小张分析一下 D:/repo 的构建脚本" | 派活：消息注入小张会话；小张完成后反馈经 S2 回流 |

### S4 销毁与级联

- 管理员（经工具或 dsh 删除流）销毁数字程序员：自动解绑（`managerId` 清除随记录删除天然成立）。
- 销毁管理员（dsh 删除流）：其全部绑定员工的 `managerId` 清空（解绑不删除）。
- 管理员工具的销毁**仅限绑定关系内**；dsh 侧人工删除不受限（所有者是人）。

## 3. 行为规格

### 3.1 类型与通道体系

- 员工记录：`type: 'pi-coder' | 'admin'`；管理员专有 `channel: 'dingtalk'`（后续 `'feishu'`）与一线员工专有 `managerId?: string`。
- 类型预设：pi-coder 沿用既有职责模板与 emoji；admin 模板为管理者职责描述 + 预设 emoji。
- 管理层职责逻辑（绑定/转发/权限）与通道实现解耦：通道只决定 Transport 选择。

### 3.2 绑定模型

- 创建员工（向导/命令/管理员工具）时自动绑定：唯一管理员自动绑，多个则显式选择（向导步骤/工具参数）。
- 销毁员工自动解绑；销毁管理员清空其全部绑定员工的 `managerId`。
- 管理员工具的销毁仅限 `managerId` 指向自身的员工；dsh 侧人工删除不受限。

### 3.3 反馈管线

- 事件源：员工会话回合结算（pi 子代理 settle，数字员工插件 manager 已观察）。
- 管线：结算 → 按 `managerId` 定位管理员 → 组装消息 → `Transport.send`；指数退避重试 3 次；重试耗尽落日志 + 管理员会话提示，不阻塞员工。
- 仅数字程序员产生反馈；管理员自身会话回合不进入反馈管线。

### 3.4 Transport

```
interface DingtalkTransport {
  send(message: OutboundMessage): Promise<void>   // 退避重试在实现内
  start(receive: (message: InboundMessage) => void): Promise<void>  // 长连接
  stop(): Promise<void>
}
```

- v1 实现（dws）：发送到私人通知群（`dws chat`，以用户身份）；接收经 `dws event` 个人长连接子进程（随插件启停、断线重连、输出解析）。
- 后续实现（企业机器人应用）：机器人 DM + 应用流式回调；凭据（appKey/appSecret/userId）入 settings 即切换，管线与工具不变。
- 通道配置（通知群 id、userId 白名单、机器人凭据字段预留）全部入 dsh settings。

### 3.5 白名单与注入

- 接收事件先比对 userId 白名单：通过 → 以来源元数据（`来源：钉钉`）注入管理员的 dsh 会话（复用直通 adapter 的 prompt 路径）→ 回答 settle 后经 Transport 回发。
- 注入遵循员工会话既有排队语义（活动轮未结束排队，不并发两轮）。

### 3.6 管理员工具（注册于管理员 pi 子代理）

| 工具 | 参数 | 语义 | 强制约束（工具实现内） |
|---|---|---|---|
| 创建数字程序员 | name, cwd | 创建并**自动绑定**本管理员 | 绑定写入即生效 |
| 销毁员工 | name 或 id | 删除指定员工 | **仅限 `managerId` 指向本管理员**；未绑定拒绝并说明 |
| 列出员工 | — | 绑定员工的名字/类型/运行状态 | 仅返回本管理员绑定集 |
| 派活 | employee, message | 消息注入该员工会话（followUp 排队语义） | 仅限已绑定员工 |
| 查询中间状态 | employee | 运行/空闲、最近反馈、最后活跃时间 | 仅限已绑定员工 |

权限校验全部在工具实现（确定性代码）：LLM 输出的工具调用若越权，工具拒绝并返回原因，LLM 据此向用户说明。

## 4. 非目标

同 OKR 非目标；另：v1 不做钉钉企业机器人应用实现（接口就位）、不做群聊多成员指令、不做反馈的持久化补发队列、不做管理员间的协作。

## 5. 需求追溯 ID（供 plan 交叉验证）

| ID | 需求 |
|---|---|
| M1 | 类型两维：`type`（pi-coder/admin）+ 管理员 `channel`（dingtalk）；类型预设（职责模板/emoji） |
| M2 | 绑定模型：`managerId` 单管理员；创建自动绑定（唯一自动/多个选择）；销毁自动解绑；管理员删除级联解绑 |
| M3 | 数字管理员双面会话：pi-as-model dsh 会话（web 可对话）；向导隐藏 cwd（固定分组目录），保留模型/思考 |
| M4 | 反馈管线：绑定数字程序员回合结算 → IM 格式化转发（2000 截断）；失败退避重试 3 次不阻塞 |
| M5 | `DingtalkTransport` 可替换接口；v1 dws 实现（私人通知群发送 + `dws event` 长连接接收、断线重连） |
| M6 | 生命周期通知：创建/销毁员工动作 IM 告知用户 |
| M7 | 双向指令：钉钉回复经 userId 白名单注入管理员会话；回复文本回发 IM |
| M8 | 管理员工具集（创建/销毁/列表/派活/查询中间状态），绑定与权限在工具实现强制；销毁仅限已绑定 |
| M9 | dsh 侧创建/销毁路径同步（自动绑定/解绑语义一致；多管理员向导选择）；人工删除不受限 |
| M10 | 通道配置（通知群 id、userId 白名单、机器人凭据预留）入 dsh settings |
